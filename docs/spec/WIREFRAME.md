> "검색엔진에 노출되지 않는다"로 읽으세요 — 열람은 누구나 가능하지만 색인은

> 사진첩은 홍보용이라는 전제로 정리했습니다. 다운로드 화면은 이제 없습니다.

## 공통 — 헤더 / 푸터

### 헤더 (모바일, sticky)
```
┌────────────────────────────────────┐
│  LIGHT             [처음이신가요] ☰ │
└────────────────────────────────────┘
```
- 좌측 LIGHT 워드마크(홈 링크), 우측에 **CTA 버튼 + 햄버거**
- CTA는 메뉴에 묻지 않고 상시 노출 — 페르소나 A의 전환 경로
- 스크롤 시 배경 불투명 처리 (Hero 위에서는 투명)

**로그인 상태 분기** — ⚠️ 아래 아바타 드롭다운안은 **구현되지 않았다.** M2에서는 더 단순한
방식(햄버거 메뉴 안에서 분기)으로 구현했다. 아바타 드롭다운은 **M3/M4로 이연**한다.

*계획안 (미구현 · 이연)*
```
비로그인 │  LIGHT            [처음이신가요] ☰
로그인   │  LIGHT                      (김) ☰    ← 프로필 아바타
```
- 아바타 탭 → 드롭다운: `나의 LIGHT` / `관리`(권한 있을 때만) / `내 정보` / `로그아웃`

*실제 구현 (M2 · `frontend/src/components/layout/Header.tsx`)*
```
헤더 우측은 로그인 여부와 무관하게 동일:  LIGHT   [처음이신가요] ☰

햄버거 메뉴 하단에서만 분기:
  비로그인 │  🔒 로그인 / 회원가입
  로그인   │  👤 {이름}님 · 나의 LIGHT
           │  로그아웃
```
- 아바타·드롭다운 없음. `관리`·`내 정보` 진입은 `/my` 타일을 통한다
- `[처음이신가요]` CTA는 로그인 상태에서도 계속 노출된다 (계획안과 다른 점)
- **공개 메뉴에 회원 메뉴를 섞지 않는다.** 비로그인 방문자에게 잠긴 문을 보여주면 혼란만 준다

### 메뉴 (햄버거 오픈, 전체화면)
```
┌────────────────────────────────────┐
│                                 ✕  │
│   소개                             │
│   예배와 모임                      │
│   말씀                             │
│   소식                             │
│   오시는 길                        │
│                                    │
│   ──────────────────────────       │
│   주일 14:00 · 드림센터 4층        │
│   [ 처음 오시는 분 ]               │
│   ▸ Instagram   ▸ YouTube          │
│   ──────────────────────────       │
│   🔒 로그인 / 회원가입             │
└────────────────────────────────────┘
```
- 메뉴를 열어도 예배 시간이 보인다 → 어느 화면에서든 2탭 안에 핵심 정보 도달
- 로그인은 메뉴 **최하단**. 공개 방문자에게 필요 없는 기능이 눈에 먼저 들어오면 안 된다

M2에서 실제로 만든 것은 상단 절반이다.

| 요소 | M2 상태 |
|---|---|
| 인사말 + 소속 마을 | ✅ 구현 |
| 공지사항 · 내 정보 타일 | ✅ 구현 (`/my/notices` · `/my/profile`로 연결) |
| 주보 · 사진첩 · 월례회 자료 타일 | **"준비 중" 비활성 타일** — 대상 화면이 M3/M4 범위 |
| 관리 타일 (콘텐츠 작성·회의록) | 임원 이상에만 렌더 + **"준비 중" 비활성** — 관리 화면은 M4 |
| 이번 주 주보 블록 | ⬜ **M3로 이연** (주보 데이터 필요) |
| 최근 앨범 블록 | ⬜ **M3로 이연** (사진첩 데이터 필요) |
| 📌 새 공지 N건 | ⬜ **이연** — 읽음 상태 추적이 필요해 M2 범위 밖 |
| `[ 홈 화면에 추가 ]` 배너 | ✅ **M4 구현** — 단 컴포넌트는 루트 레이아웃에 마운트되고 스스로 `/my`에서만 렌더한다 (`/my` 하위 화면을 덮지 않기 위해) |

> **"준비 중" 비활성 타일**은 와이어프레임에 없던 실제 구현 상태다. 아직 못 만든 기능을
> 링크로 걸어 404로 보내지 않고, 자리와 순서는 보여주되 누를 수 없게 했다
> (`/news`의 비활성 "갤러리" 탭과 같은 방식).

### 14-1b. 공지 상세 `/my/notices/[slug]`
공개 공지 상세(§7)와 동일한 레이아웃을 재사용한다 — 제목·작성자·날짜·본문·첨부.
차이는 **회원 전용 경로라 로그인·승인 상태를 확인한다**는 점뿐이다.
내부 글(`NOTICE_MEMBER`)과 공개 글 모두 이 경로로 열린다.

### 14-2. 내 정보 상세 동작
위 패널의 `▸` 항목은 **별도 화면으로 이동하지 않고 같은 페이지에서 펼쳐진다.**

```
▸ 비밀번호 변경  →  현재 비밀번호 [______]
                    새 비밀번호   [______]
                    새 비밀번호 확인 [______]   (8자 이상)
                    [ 변경하기 ]

▸ 로그아웃       →  즉시 실행 → `/`로 이동

▸ 회원 탈퇴      →  ⚠️ 안내 문구 + 비밀번호 [______]
                    [ 탈퇴하기 ]  → confirm() 확인 → 실행
```
- **회원 탈퇴의 "확인 절차"(FR-AUTH-11)는 비밀번호 재입력 + `confirm()` 2단계다.**
  되돌릴 수 없는 동작이라 클릭 한 번으로 실행되지 않게 했다
- 연락처 `수정`은 인라인 입력 → 저장 시 즉시 반영 (`PATCH /api/auth/me`)
- 권한 표기: `MEMBER`→일반 회원 · `LEADER`→임원 · `PASTOR`→목회자 (~~`PENDING`~~ 2026-08-31 소멸)

### 21-1. 변환 진행 상태
```
┌────────────────────────────────────┐
│  자료를 변환하고 있습니다          │
│  ⏳ 12초 경과 · 보통 15~30초        │
│  ⓘ 창을 닫지 마세요                │
└────────────────────────────────────┘
```
- PDF → 페이지 이미지 변환은 **10페이지 기준 15~30초** 소요 (ARCH §7.7). 동기 처리
- 변환 중 이탈 경고. 실패 시 원인 표시(암호 걸린 PDF·손상 등)
- ⚠️ **`7 / 10 페이지` 형태의 페이지별 진행률은 구현하지 않았다** (2026-08-25 정정).
  서버가 변환을 **동기 처리**하므로 응답이 오기 전까지 지금 몇 페이지째인지
  알 방법이 없다 — 진행률을 보여주려면 SSE나 job id 폴링 통로가 필요하고,
  그건 백엔드 계약에 없다(`BACKEND_HANDOFF` 2026-08-25 `[논의]` 항목).
  대신 **경과 시간**과 예상 소요를 보여준다. 가짜 진행률 바로 채워 보이는
  쪽이 더 나쁘다 — 멈춘 것인지 도는 것인지를 사용자가 판단할 수 없게 된다.

- ⚠️ **업로드 화면의 경고 문구가 이 기능에서 가장 중요한 UI다.**
  "막았다"고 믿고 더 민감한 자료를 올리는 것이 최악의 결과다 (ARCH §7.7)
- 열람 기간은 필수. 기본값은 월례회 일자 20:00 ~ +2일 23:59
- 업로드 후 기간 연장·조기 종료 가능
- **원본 Word·PDF는 서버에 보관하지 않는다** (유출 경로 제거, ARCH §7.7)
- 페이지 순서는 PDF 순서를 따르므로 수동 정렬 UI가 필요 없다

## 22. 출석부 `/admin/attendance` · `/admin/attendance/[id]` ★신규 (2026-08-28)

> **§9 제외 목록에 있던 기능의 편입이다** — 범위·근거는 `SPEC_FUNCTIONAL §11` ·
> `SPEC_API §13`. 권한은 전부 임원(`L`) 이상. **FE는 mock으로 구현 완료,
> BE는 재설계 확정 후 착수.**

### 22a. 회차 목록 `/admin/attendance`
```
┌────────────────────────────────────┐
│  ← 관리                            │
│  출석부                            │
│  회차를 만들고 눌러서 출결 체크    │
├────────────────────────────────────┤
│  회차 만들기                       │
│  [날짜 ▾] [종류 ▾] [이름________]  │
│              [ 만들고 체크 시작 ]  │
├────────────────────────────────────┤
│  8/24 (일)  주일예배    체크 4/15  │
│  ──────────────────────────        │
│  8/17 (일)  주일예배    출석 11명  │
└────────────────────────────────────┘
```
- **만들기 폼이 목록 위에 인라인**이다 (별도 페이지 없음) — 입력이 날짜·이름
  둘뿐이고, 주 사용 흐름이 "주일 아침에 열어서 → 오늘 회차 만들고 → 바로
  체크"라 화면 전환 하나가 그대로 비용이다. 생성 성공 시 22b로 즉시 이동
- 행 우측은 **진행 상태**다: 체크가 덜 끝났으면 "체크 4/15"(분모는 명단 전체),
  다 끝났으면 "출석 n명" — 완료된 회차에서 15/15는 정보가 아니다
- 날짜는 요일까지 표시 ("8/24 (일)") — 회차의 정체성이 날짜다

### 22b. 출석 체크 `/admin/attendance/[id]`
```
┌────────────────────────────────────┐
│  ← 출석부                          │
│  8/24 (일) 주일예배     체크 4/15  │
├────────────────────────────────────┤
│  1마을                             │
│  강OO •  [출석][지각][결석][공결]  │
│  김OO    [출석][지각][결석][공결]  │
│  ⋮                                 │
│  2마을                             │
│  정OO    [출석][지각][결석][공결]  │
│  ⋮                                 │
├────────────────────────────────────┤
│  저장 안 된 체크 2건      [ 저장 ] │ ← 하단 고정
└────────────────────────────────────┘
```
- **명단 전원**이 마을 그룹으로 나온다 — 계정 없는 교인 포함. 임원이 자기
  마을부터 훑는 흐름을 전제한다
- 상태 버튼 4개는 **개별 토글**(`aria-pressed`)이다. radiogroup이 아닌 이유:
  미체크(아무것도 선택 안 됨)가 유효한 상태다 — "기록 없음"과 "결석"은 다르다
- 탭할 때마다 저장하지 않는다. 이름 옆 `•`가 미저장 표시이고, **하단 고정
  저장 바**가 미저장 개수를 상시 보여준다 → [저장]이 변경분만 한 번에 보낸다
  (`SPEC_API §13.4` upsert — 두 임원이 동시에 다른 마을을 체크해도 안전)
- 저장 전 이탈을 확인창으로 막지 않는다 — 대신 미저장 상태가 항상 눈에 보인다
- 버튼 색: 출석·지각은 긍정(노랑 계열), 결석은 경고(빨강), 공결은 중립
- 회차 삭제 버튼은 1차에 없다 (`FR-ATT-05`)
