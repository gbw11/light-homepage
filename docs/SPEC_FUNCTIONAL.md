## 0. 읽는 방법

### 0.1 ID 체계
```
FR-<영역>-<번호>
  PUB  공개 영역        AUTH 인증·회원
  MEM  회원 영역        BUL  주보
  PHO  사진첩           MTG  월례회
  DOC  문서(공지·회의록·예산안)
  ADM  관리
```

### 0.2 역할 표기
| 표기 | 역할 |
|---|---|
| `G` | GUEST — 비로그인 |
| `P` | PENDING — 가입했으나 미승인 |
| `M` | MEMBER — 승인된 회원 |
| `L` | LEADER — 임원 |
| `T` | PASTOR — 전도사님 (계단식 상위) |

권한은 계단식입니다. `M` 표기는 `M·L·T` 모두 가능함을 뜻합니다.

### 0.3 우선순위
마일스톤과 일치합니다. `M1` = 공개 사이트 · `M2` = 인증·회원 · `M3` = 사진첩·주보 · `M4` = 문서·월례회·품질

### 1.1 수용 기준 (핵심만)

**FR-PUB-01** — 모바일에서 **스크롤 없이** 예배 시간·장소·CTA가 모두 보인다.

**FR-PUB-02** — 페이지 최상단이 "드림센터 찾기"다. 본당(가락로 117)과 드림센터의 위치 관계를 **약도 또는 사진으로** 확인할 수 있다.
> 드림센터가 본당과 별개 건물이어서, 주소만 보고 온 방문자가 길을 잃는 것이 이 사이트의 최대 이탈 지점이다.

**FR-PUB-08**
- 동의 체크 전에는 제출 버튼이 비활성
- 서버에서도 `agreed === true`를 재검증한다 → 미동의 요청은 `VALIDATION_ERROR`
- 제출 성공 시 담당자에게 알림 메일이 발송된다
- 동일 IP 5분 내 5회 초과 제출은 거부한다

**FR-PUB-10** — 공개 페이지는 **백엔드 없이도 렌더된다.** 백엔드 장애·슬립 시에도 공개 영역은 정상 동작해야 한다.

## 2. 인증·회원 (FR-AUTH)

FE는 `SPEC_API.md §2` 계약대로 mock/real 양쪽을 구현했다 (`frontend/src/lib/api`). 아래 상태는 **FE 기준**이며, BE(Spring Security·JWT)는 아직 미착수다.

| ID | 기능 | 권한 | M | 상태 | 상세 |
|---|---|---|---|---|---|
| FR-AUTH-01 | 이메일 회원가입 | G | M2 | 🟡 | 이름(실명)·이메일·비밀번호·연락처·소속마을 + 개인정보 동의. 가입 시 `role=PENDING` — `/signup` |
| FR-AUTH-02 | 카카오 로그인 | G | M2 | 🟡 부분 | 카카오 OAuth. 신규 계정은 `PENDING` 생성 후 추가정보 화면으로 — **FE는 `/api/auth/kakao/authorize`로 이동하는 버튼만 구현.** 302 왕복은 BE 구현 후에야 동작한다 |
| FR-AUTH-03 | 카카오 추가정보 입력 | P | M2 | 🟡 부분 | 실명·연락처·소속마을 필수 입력 (승인 대조용) — `/signup/complete`. **"카카오 닉네임" 표시는 임시로 `me()`의 `name`을 씀** (실제 닉네임 소스 미정, `BACKEND_HANDOFF.md` 참고) |
| FR-AUTH-04 | 로그인 | G | M2 | 🟡 | 이메일+비밀번호. JWT를 httpOnly 쿠키로 발급 — `/login` |
| FR-AUTH-05 | 자동 토큰 갱신 | M | M2 | ⬜ | 액세스 토큰(30분) 만료 시 리프레시 토큰(14일)으로 자동 재발급 — **미구현.** `api.auth.refresh()` 함수는 있으나 401 감지 후 자동 재시도하는 인터셉터가 없다 (`SPEC_API.md §12.2`) |
| FR-AUTH-06 | 로그아웃 | M | M2 | 🟡 | 쿠키 삭제 + 리프레시 토큰 DB에서 폐기 — Header · `/my/profile` |
| FR-AUTH-07 | 승인 대기 안내 | P | M2 | 🟡 | `PENDING` 상태로 회원 경로 접근 시 대기 화면 고정 — `/pending` + `RequireMember` (⚠️ UI 편의, 실제 차단은 BE 책임) |
| FR-AUTH-08 | 비밀번호 재설정 | G | M2 | 🟡 | 이메일로 1회용·만료 토큰 발송 → 새 비밀번호 설정 — `/password/reset-request` · `/password/reset` |
| FR-AUTH-09 | 내 정보 조회·수정 | M | M2 | 🟡 | 이름·연락처·마을 조회. 연락처 수정 가능 — `/my/profile` |
| FR-AUTH-10 | 비밀번호 변경 | M | M2 | 🟡 | 현재 비밀번호 확인 후 변경 — `/my/profile` |
| FR-AUTH-11 | 회원 탈퇴 | M | M2 | 🟡 | 확인 절차 후 계정 삭제. 개인정보 즉시 파기 — `/my/profile`. **확인 절차 = 비밀번호 재입력 + `confirm()`** |

### 2.1 수용 기준

**FR-AUTH-01 / 02** — **가입 즉시 회원이 되지 않는다.** `PENDING` → 관리자 승인 → `MEMBER`.
> 승인 절차가 없으면 아무나 가입해 내부 자료(회의록·예산안·월례회)를 볼 수 있다. **타협 불가 항목이다.**

**FR-AUTH-02 / 03**
- 카카오 이메일 수집은 비즈 앱 전환이 필요하므로, **이메일 없이도 계정이 생성되어야 한다** (`kakao_id`로 식별)
- 카카오 닉네임은 실명이 아닌 경우가 많으므로 **실명을 별도로 받는다**
- 추가정보 입력을 완료하지 않으면 승인 대상에 오르지 않는다

**FR-AUTH-04** — JWT는 `HttpOnly; Secure; SameSite=Lax` 쿠키로만 전달한다. **localStorage에 저장하지 않는다.**

**FR-AUTH-07** — `PENDING` 계정은 로그인은 되지만 모든 회원 API가 `PENDING_APPROVAL`을 반환한다.

## 3. 회원 영역 (FR-MEM)

로그인 + 승인 필요. 검색엔진 색인을 차단합니다(`noindex`).

| ID | 기능 | 권한 | M | 상태 | 상세 |
|---|---|---|---|---|---|
| FR-MEM-01 | 회원 홈 (나의 LIGHT) | M | M2 | 🟡 부분 | 아이콘 타일(주보·사진첩·공지·내정보) + 권한 있으면 관리 타일 — `/my`. **구현된 것**: 인사말·마을 표시, 타일 그리드, 임원 이상에만 관리 타일 렌더. **미구현(M3/M4로 이연)**: 이번주 주보·최근 앨범·새 공지 알림 — 주보/사진첩 데이터가 M3 범위라서. 해당 타일들은 "준비 중" 비활성 상태로 표시된다 |
| FR-MEM-02 | 내부 공지 목록·상세 | M | M2 | 🟡 | 공개 공지 + 내부 공지 통합 목록. 내부 글에 🔒 표시 — `/my/notices`, `/my/notices/[slug]`. 고정 글은 📌도 함께 표시. 병합·정렬은 FE에서 두 카테고리를 각각 받아 처리 |
| FR-MEM-03 | PWA 설치 | M | M4 | ⬜ | 홈 화면 추가. 회원 첫 방문 시 설치 배너 1회 노출 |

### 3.1 수용 기준

**FR-MEM-01** — 권한 없는 메뉴는 렌더하지 않는다. **단 이것은 편의 기능이며 보안이 아니다.** 서버에서 반드시 차단해야 한다.

**FR-MEM-03** — PWA 서비스워커는 **회원 데이터를 캐싱하지 않는다.** 주보·사진·문서를 캐싱하면 로그아웃 후에도 남는다. 캐시 대상은 정적 자산과 공개 페이지 셸로 한정한다.

## 5. 사진첩 (FR-PHO)

회원 재방문의 핵심 동기입니다.

| ID | 기능 | 권한 | M | 상세 |
|---|---|---|---|---|
| FR-PHO-01 | 앨범 목록 | M | M3 | 커버 사진·제목·행사일·사진 수. 최신순 |
| FR-PHO-02 | 앨범 상세 (그리드) | M | M3 | 3열 썸네일 그리드. 커서 기반 무한 스크롤 |
| FR-PHO-03 | 확대 보기 (라이트박스) | M | M3 | 좌우 스와이프, 핀치 줌, 위치 표시(12/243) |
| FR-PHO-04 | 개별 다운로드 | M | M3 | 라이트박스에서 원본(2560px) 다운로드 |
| FR-PHO-05 | 선택 다운로드 | M | M3 | 체크박스로 여러 장 선택 → ZIP. **최대 30장** |
| FR-PHO-06 | 사진 신고·삭제 요청 | M | M4 | 초상권 대응. 요청 시 임원에게 전달 |
| FR-PHO-07 | 앨범 생성 | L | M3 | 제목·행사일 |
| FR-PHO-08 | 사진 대량 업로드 | L | M3 | 다중 선택, **200장 이상**, 진행률, **부분 실패 재시도** |
| FR-PHO-09 | 사진·앨범 삭제 | L | M3 | R2 객체까지 함께 삭제 |
| FR-PHO-10 | 저장 용량 표시 | L | M3 | `4.2GB / 10GB` 게이지. **80% 경고 · 95% 업로드 차단** |
| FR-PHO-11 | 앨범 아카이브 | L | M4 | 오래된 앨범을 내려받아 외부 보관 후 R2에서 제거 |

### 5.1 수용 기준

**FR-PHO-02 / 03 / 04** — 열람은 **썸네일(640px)**, 다운로드만 **원본(2560px)**.
> 앨범 200장을 열어도 전송량이 약 16MB에 머물러야 한다.

**FR-PHO-04** — ⚠️ 보관되는 최대 화질은 **장변 2560px**이다. 촬영 원본은 보관하지 않는다.
휴대폰 감상·SNS 공유·A4 인쇄에는 충분하나 인쇄·보정용 원본이 아니며, 이 경계를 화면에 안내한다.

**FR-PHO-08** — 다음이 모두 충족되어야 한다.
- 브라우저에서 리사이즈(2560/640) 후 업로드 → 파일이 백엔드를 통과하지 않는다
- 동시 3~4개씩 큐 처리 (전부 병렬 금지)
- 전체/완료/실패 개수 + 진행률 표시
- **실패한 항목만 재시도** 가능 (243장 중 2장 실패에 전체 재업로드를 요구하지 않는다)
- 업로드 중 페이지 이탈 경고

**FR-PHO-10** — 무료 한도(10GB)를 넘기면 과금이 시작된다. **조용히 과금되는 것보다 업로드를 막는 것이 낫다.**

## 6. 월례회 자료 (FR-MTG)

2개월마다 열리는 월례회 자료를 **열람 기간 내에만, 보기 전용**으로 제공합니다.

| ID | 기능 | 권한 | M | 상세 |
|---|---|---|---|---|
| FR-MTG-01 | 월례회 목록 | M | M4 | 열람 가능/종료 상태 표시. 남은 시간 표시 |
| FR-MTG-02 | 자료 열람 | M | M4 | 페이지 이미지 스와이프. **열람 기간 내에만** |
| FR-MTG-03 | 워터마크 | M | M4 | 열람자 **이름·연락처 뒷4자리·열람시각**을 이미지에 합성 |
| FR-MTG-04 | 다운로드 차단 | M | M4 | 파일 URL 미발급. 저장 제스처 차단 |
| FR-MTG-05 | 기간 종료 처리 | M | M4 | 종료 후 목록에 `종료됨`으로 남고 열람 불가 |
| FR-MTG-06 | 임원 상시 열람 | L | M4 | 임원 이상은 기간 제약 없이 열람 |
| FR-MTG-07 | 자료 업로드 | L | M4 | **PDF 업로드** → 서버가 페이지 이미지로 변환. 열람 기간 설정 |
| FR-MTG-08 | 열람 기간 수정 | L | M4 | 연장·조기 종료 |
| FR-MTG-09 | 열람 로그 | L | M4 | 누가·언제·몇 페이지를 봤는지 |

### 6.1 ⚠️ 이 기능의 한계 (반드시 인지)

**웹에서 스크린샷을 차단하는 것은 원천적으로 불가능합니다.** 브라우저에 그런 API가 없고, iOS는 네이티브 앱에서도 막을 수 없으며, 다른 기기로 화면을 촬영하는 것은 어떤 방법으로도 막을 수 없습니다.

따라서 이 기능의 목표는 **"기술적 차단"이 아니라 "쉬운 유출 차단 + 유출 시 추적"** 입니다.

| 통제 | 강도 |
|---|---|
| 열람 기간 제한 (서버 검사) | 강함 |
| 다운로드 경로 차단 (서버 스트리밍) | 강함 |
| **워터마크 burn-in** | **가장 실효적** |
| 저장 제스처 차단 | 약함 — 개발자도구로 우회 가능 |
| 열람 로그 | 중간 (사후 추적) |

**핵심은 워터마크입니다.** 캡처를 막을 수 없으므로 "캡처하면 내 이름이 박힌다"는 사실이 실제 억제력을 만듭니다.

> ⚠️ **운영진에게 이 한계를 반드시 고지해야 합니다.** 막았다고 믿고 더 민감한 자료를 올리는 것이 가장 위험한 결과입니다.

### 6.2 수용 기준

**FR-MTG-02 / 05** — 기간 판정은 **서버에서만** 한다. 프론트에서 날짜를 계산해 숨기는 방식은 우회 가능하다.

**FR-MTG-03** — 워터마크는 **서버에서 이미지에 합성**한다. CSS 오버레이는 개발자도구로 제거되므로 사용하지 않는다.

**FR-MTG-04** — presigned URL을 발급하지 않는다. 발급하면 그 URL이 기간 종료 후에도 만료 전까지 살아있고 공유 가능해진다. **서버가 직접 스트리밍한다.**

**FR-MTG-07**
- 원본은 Word 문서다. 업로더가 Word에서 **「PDF로 저장」** 후 PDF를 올린다
- 서버가 PDFBox로 페이지 이미지(장변 2048px)로 변환한다
- **업로드한 PDF 원본은 보관하지 않는다** — 남으면 그 자체가 유출 경로가 된다
- 10페이지 내외 기준 변환 15~30초. 진행 상태를 표시한다

## 7. 문서 게시판 (FR-DOC)

공지·회의록·예산안을 하나의 게시판으로 구현하고 분류로 구분합니다.

| ID | 기능 | 권한 | M | 상세 |
|---|---|---|---|---|
| FR-DOC-01 | 글 작성 | L | M4 | 분류 선택 + 제목 + **리치텍스트 본문** + 첨부파일 + 상단고정 |
| FR-DOC-02 | 글 수정·삭제 | L | M4 | 첨부 추가·제거 포함 |
| FR-DOC-03 | 회의록 목록·상세 | L | M4 | `MINUTES` 분류 |
| FR-DOC-04 | 예산안 목록·상세 | L | M4 | `BUDGET` 분류 |
| FR-DOC-05 | 첨부파일 다운로드 | 상속 | M4 | 게시물 열람 권한을 그대로 상속. **서명된 임시 URL** |
| FR-DOC-06 | 공개 범위 경고 | L | M4 | 분류 변경 시 "누가 볼 수 있는지"를 실시간 표시 |

### 7.1 분류와 권한

| 분류 | 열람 | 작성 |
|---|---|---|
| `NOTICE_PUBLIC` 공개 공지 | 누구나 | L |
| `NOTICE_MEMBER` 내부 공지 | M | L |
| `MINUTES` 회의록 | **L** | L |
| `BUDGET` 예산안 | **L** | L |

> 회의록과 예산안의 접근 권한이 동일합니다(임원 이상). 분류는 목록 구분 목적으로만 유지합니다.

### 7.2 수용 기준

**FR-DOC-06** — **분류 선택이 곧 공개 범위 결정이다.** 잘못 고르면 예산안이 공개된다.
→ 드롭다운에 각 분류가 누구에게 보이는지 항상 함께 표시하고, 공개 분류를 골랐을 때 경고 배너를 띄운다.

**FR-DOC-05** — 파일 주소를 아는 것만으로 열려서는 안 된다. 로그아웃 상태에서 첨부 URL을 열면 거부된다.

## 8. 관리 (FR-ADM)

⚠️ `M` 열의 **M2는 백엔드 기준**이다 (`WORKPLAN.md` M2 BE: "회원 승인·역할부여·자기잠금방지").
**FE 관리 화면은 M4**로 계획돼 있다 (`WORKPLAN.md §11.1` #38 회원 관리 UI) — 그래서 M2 FE 완료
시점에도 이 영역은 전부 ⬜다.

|---|---|---|---|---|---|
| FR-ADM-01 | 관리 홈 | L | M4 | ⬜ | 승인 대기 알림, **저장 용량 표시**, 기능 진입점, 역할 배지 |
| FR-ADM-02 | 승인 대기 목록 | **T** | M2 | ⬜ (FE는 M4) | 이름·마을·연락처·신청일. 승인/거절 |

| FR-ADM-06 | 감사 로그 기록 | — | M2 | — (BE 전용) | 승인·거절·역할 변경을 기록 |

### 8.1 수용 기준

**FR-ADM-04** — 되돌리기 어려운 동작이므로 확인 모달을 거친다. 변경 이력은 `audit_logs`에 남는다.

**FR-ADM-05** — 마지막 전도사가 자신을 강등하면 아무도 회원을 승인할 수 없게 된다. 애플리케이션에서 `PASTOR` 수가 0이 되는 변경을 거부한다.

**FR-ADM-07** — 개인정보이므로 **보유기간 1년 후 삭제** 안내를 화면에 표시한다.
