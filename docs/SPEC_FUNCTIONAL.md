## 0. 읽는 방법

### 0.1 ID 체계
```
FR-<영역>-<번호>
  PUB  공개 영역        AUTH 인증·회원
  MEM  회원 영역        BUL  주보
  PHO  사진첩           MTG  월례회
  DOC  문서(공지·회의록·예산안)
  ADM  관리
```

### 0.2 역할 표기
| 표기 | 역할 |
|---|---|
| `G` | GUEST — 비로그인 |
| `P` | PENDING — 가입했으나 미승인 |
| `M` | MEMBER — 승인된 회원 |
| `L` | LEADER — 임원 |
| `T` | PASTOR — 전도사님 (계단식 상위) |

권한은 계단식입니다. `M` 표기는 `M·L·T` 모두 가능함을 뜻합니다.

### 0.2-1 ⚠️ 2026-08-25 권한 모델 전환 — 아래 표의 권한 열을 읽는 방법

**PM 결정으로 사이트의 기본 상태가 "로그인 없이 열람 가능"이 됐습니다**
(`docs/DECISIONS.md` 2026-08-25 · `docs/handoff/2026-08-25-public-read-model.md`).
개별 행의 권한 열은 아직 전환 이전 값(`M`)으로 남아 있는 곳이 있으니, 다음
규칙을 얹어서 읽으세요.

| 종류 | 실제 권한 |
|---|---|
| **열람** (목록·상세·개별 다운로드) | **`G` — 비로그인 포함 누구나.** 표에 `M`으로 적혀 있어도 그렇습니다 |
| **쓰기·관리** (업로드·수정·삭제·기간 관리) | 표 그대로 (`L` 또는 `T`) |
| **예외 — 예산안(`BUDGET`) 열람** | **`L` 이상 유지.** 헌금·지출 내역이 담기는 유일한 예외입니다. 권한이 없으면 서버가 `404`로 존재를 숨깁니다 |
| **예외 — 월례회 기간 외 열람** | `L` 이상. 익명·일반 회원은 `OPEN` 자료만 |
| **본인 정보**(`/my/profile`) | 본인(`M` 이상) |

로그인의 의미도 바뀌었습니다: **자료를 올리거나 관리해야 하는 사람(임원·전도사)의
관문**입니다. 일반 회원(`MEMBER`) 계정은 비로그인 방문자와 할 수 있는 일이
같아서, 회원가입 진입점은 화면에서 숨겨져 있습니다(라우트는 보존).

### 0.3 우선순위
마일스톤과 일치합니다. `M1` = 공개 사이트 · `M2` = 인증·회원 · `M3` = 사진첩·주보 · `M4` = 문서·월례회·품질

### 1.1 수용 기준 (핵심만)

**FR-PUB-01** — 모바일에서 **스크롤 없이** 예배 시간·장소·CTA가 모두 보인다.

**FR-PUB-02** — 페이지 최상단이 "드림센터 찾기"다. 본당(가락로 117)과 드림센터의 위치 관계를 **약도 또는 사진으로** 확인할 수 있다.
> 드림센터가 본당과 별개 건물이어서, 주소만 보고 온 방문자가 길을 잃는 것이 이 사이트의 최대 이탈 지점이다.

**FR-PUB-08**
- 동의 체크 전에는 제출 버튼이 비활성
- 서버에서도 `agreed === true`를 재검증한다 → 미동의 요청은 `VALIDATION_ERROR`
- 제출 성공 시 담당자에게 알림 메일이 발송된다
- 동일 IP 5분 내 5회 초과 제출은 거부한다

**FR-PUB-10** — 공개 페이지는 **백엔드 없이도 렌더된다.** 백엔드 장애·슬립 시에도 공개 영역은 정상 동작해야 한다.

## 2. 인증·회원 (FR-AUTH)

FE는 `SPEC_API.md §2` 계약대로 mock/real 양쪽을 구현했다 (`frontend/src/lib/api`). 아래 상태는 **FE 기준**이며, BE(Spring Security·JWT)는 아직 미착수다.

| ID | 기능 | 권한 | M | 상태 | 상세 |
|---|---|---|---|---|---|
| FR-AUTH-01 | 이메일 회원가입 | G | M2 | 🟡 | 이름(실명)·이메일·비밀번호·연락처·소속마을 + 개인정보 동의. 가입 시 `role=PENDING` — `/signup` |
| FR-AUTH-02 | 카카오 로그인 | G | M2 | 🟡 부분 | 카카오 OAuth. 신규 계정은 `PENDING` 생성 후 추가정보 화면으로 — **FE는 `/api/auth/kakao/authorize`로 이동하는 버튼만 구현.** 302 왕복은 BE 구현 후에야 동작한다 |
| FR-AUTH-03 | 카카오 추가정보 입력 | P | M2 | 🟡 부분 | 실명·연락처·소속마을 필수 입력 (승인 대조용) — `/signup/complete`. **"카카오 닉네임" 표시는 임시로 `me()`의 `name`을 씀** (실제 닉네임 소스 미정, `BACKEND_HANDOFF.md` 참고) |
| FR-AUTH-04 | 로그인 | G | M2 | 🟡 | 이메일+비밀번호. JWT를 httpOnly 쿠키로 발급 — `/login` |
| FR-AUTH-05 | 자동 토큰 갱신 | M | M2 | 🟡 | 액세스 토큰(30분) 만료 시 리프레시 토큰(14일)으로 자동 재발급 — `frontend/src/lib/api/real.ts`의 `request()`가 401 → `/auth/refresh` 1회 → 원래 요청 재시도. 리프레시 토큰 회전 때문에 동시 401은 single-flight로 묶는다. 실패 시 `session.ts`로 알려 `/login`으로 (`SPEC_API.md §12.2`). ⚠️ **실제 401 왕복은 BE 인증 구현 후에야 검증 가능** |
| FR-AUTH-06 | 로그아웃 | M | M2 | 🟡 | 쿠키 삭제 + 리프레시 토큰 DB에서 폐기 — Header · `/my/profile` |
| FR-AUTH-07 | 승인 대기 안내 | P | M2 | 🟡 | `PENDING` 상태로 회원 경로 접근 시 대기 화면 고정 — `/pending` + `RequireMember` (⚠️ UI 편의, 실제 차단은 BE 책임) |
| FR-AUTH-08 | 비밀번호 재설정 | G | M2 | 🟡 | 이메일로 1회용·만료 토큰 발송 → 새 비밀번호 설정 — `/password/reset-request` · `/password/reset` |
| FR-AUTH-09 | 내 정보 조회·수정 | M | M2 | 🟡 | 이름·연락처·마을 조회. 연락처 수정 가능 — `/my/profile` |
| FR-AUTH-10 | 비밀번호 변경 | M | M2 | 🟡 | 현재 비밀번호 확인 후 변경 — `/my/profile` |
| FR-AUTH-11 | 회원 탈퇴 | M | M2 | 🟡 | 확인 절차 후 계정 삭제. 개인정보 즉시 파기 — `/my/profile`. **확인 절차 = 비밀번호 재입력 + `confirm()`** |

### 2.1 수용 기준

**FR-AUTH-01 / 02** — **가입 즉시 회원이 되지 않는다.** `PENDING` → 관리자 승인 → `MEMBER`.
> 승인 절차가 없으면 아무나 가입해 내부 자료(회의록·예산안·월례회)를 볼 수 있다. **타협 불가 항목이다.**

**FR-AUTH-02 / 03**
- 카카오 이메일 수집은 비즈 앱 전환이 필요하므로, **이메일 없이도 계정이 생성되어야 한다** (`kakao_id`로 식별)
- 카카오 닉네임은 실명이 아닌 경우가 많으므로 **실명을 별도로 받는다**
- 추가정보 입력을 완료하지 않으면 승인 대상에 오르지 않는다

**FR-AUTH-04** — JWT는 `HttpOnly; Secure; SameSite=Lax` 쿠키로만 전달한다. **localStorage에 저장하지 않는다.**

**FR-AUTH-07** — `PENDING` 계정은 로그인은 되지만 모든 회원 API가 `PENDING_APPROVAL`을 반환한다.

## 3. 회원 영역 (FR-MEM)

로그인 + 승인 필요. 검색엔진 색인을 차단합니다(`noindex`).

| ID | 기능 | 권한 | M | 상태 | 상세 |
|---|---|---|---|---|---|
| FR-MEM-01 | 회원 홈 (나의 LIGHT) | M | M2 | 🟡 부분 | 아이콘 타일(주보·사진첩·공지·내정보) + 권한 있으면 관리 타일 — `/my`. 인사말·마을 표시, 타일 그리드, 임원 이상에만 관리 타일 렌더. **이번주 주보·최근 앨범 미리보기 구현 완료**(M3 데이터가 생겨 이연 해제) — 각 칸은 데이터가 없으면 스스로 렌더하지 않는다. **남은 것: 새 공지 알림**(M5 Web Push 범위) |
| FR-MEM-02 | 내부 공지 목록·상세 | M | M2 | 🟡 | 공개 공지 + 내부 공지 통합 목록. 내부 글에 🔒 표시 — `/my/notices`, `/my/notices/[slug]`. 고정 글은 📌도 함께 표시. 병합·정렬은 FE에서 두 카테고리를 각각 받아 처리 |
| FR-MEM-03 | PWA 설치 | M | M4 | 🟡 | 홈 화면 추가. 회원 첫 방문 시 설치 배너 1회 노출 — manifest·서비스워커·오프라인 폴백·설치 배너. **회원 데이터 미캐싱을 화이트리스트로 보장**하고 캐시 전량 덤프로 검증(위반 0건). iOS는 공유 시트 안내, 카카오 인앱 브라우저는 설치 불가라 안내 없음 |

### 3.1 수용 기준

**FR-MEM-01** — 권한 없는 메뉴는 렌더하지 않는다. **단 이것은 편의 기능이며 보안이 아니다.** 서버에서 반드시 차단해야 한다.

**FR-MEM-03** — PWA 서비스워커는 **회원 데이터를 캐싱하지 않는다.** 주보·사진·문서를 캐싱하면 로그아웃 후에도 남는다. 캐시 대상은 정적 자산과 공개 페이지 셸로 한정한다.

### 6.1 ⚠️ 이 기능의 한계 (반드시 인지)

**웹에서 스크린샷을 차단하는 것은 원천적으로 불가능합니다.** 브라우저에 그런 API가 없고, iOS는 네이티브 앱에서도 막을 수 없으며, 다른 기기로 화면을 촬영하는 것은 어떤 방법으로도 막을 수 없습니다.

따라서 이 기능의 목표는 **"기술적 차단"이 아니라 "쉬운 유출 차단 + 유출 시 추적"** 입니다.

| 통제 | 강도 |
|---|---|
| 열람 기간 제한 (서버 검사) | 강함 |
| 다운로드 경로 차단 (서버 스트리밍) | 강함 |
| **워터마크 burn-in** | **가장 실효적** |
| 저장 제스처 차단 | 약함 — 개발자도구로 우회 가능 |
| 열람 로그 | 중간 (사후 추적) |

**핵심은 워터마크입니다.** 캡처를 막을 수 없으므로 "캡처하면 내 이름이 박힌다"는 사실이 실제 억제력을 만듭니다.

> ⚠️ **운영진에게 이 한계를 반드시 고지해야 합니다.** 막았다고 믿고 더 민감한 자료를 올리는 것이 가장 위험한 결과입니다.

### 6.2 수용 기준

**FR-MTG-02 / 05** — 기간 판정은 **서버에서만** 한다. 프론트에서 날짜를 계산해 숨기는 방식은 우회 가능하다.

**FR-MTG-03** — 워터마크는 **서버에서 이미지에 합성**한다. CSS 오버레이는 개발자도구로 제거되므로 사용하지 않는다.

**FR-MTG-04** — presigned URL을 발급하지 않는다. 발급하면 그 URL이 기간 종료 후에도 만료 전까지 살아있고 공유 가능해진다. **서버가 직접 스트리밍한다.**

**FR-MTG-07**
- 원본은 Word 문서다. 업로더가 Word에서 **「PDF로 저장」** 후 PDF를 올린다
- 서버가 PDFBox로 페이지 이미지(장변 2048px)로 변환한다
- **업로드한 PDF 원본은 보관하지 않는다** — 남으면 그 자체가 유출 경로가 된다
- 10페이지 내외 기준 변환 15~30초. 진행 상태를 표시한다

### 8.1 수용 기준

**FR-ADM-04** — 되돌리기 어려운 동작이므로 확인 모달을 거친다. 변경 이력은 `audit_logs`에 남는다.

**FR-ADM-07** — 개인정보이므로 **보유기간 1년 후 삭제** 안내를 화면에 표시한다.
