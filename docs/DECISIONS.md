# PM 결정 기록

PM(프론트엔드·인프라·기획 총괄)이 대화 중 구두로 전달한 스펙 결정·변경사항을
모아두는 로그다. **여기 있는 항목은 PM이 별도로 다시 요청하지 않아도, 결정이
나올 때마다 자동으로 추가된다** (`frontend/docs/HARNESS.md` §1 규칙).

목적: 백엔드 담당자를 포함해 이 대화에 없었던 사람도, 왜 화면/기능이 이렇게
바뀌었는지 나중에 추적할 수 있게 한다. `docs/SPEC_FUNCTIONAL.md`/
`docs/WIREFRAME.md`의 확정 스펙과는 별개로, **아직 그 문서에 반영되지 않은
최신 결정**을 여기서 먼저 확인할 수 있다.

형식: 최신 항목이 위에 온다.

로그인 진입점을 두고, 로그인한(승인된) 사용자에게만 파일 업로드·사진 추가·

`feat/fe-public-read-model`)

- **영역**: 프론트엔드 + **백엔드 인가 매트릭스 변경 필요** (`BACKEND_HANDOFF.md`
  2026-08-25 항목 참고)
- **공개로 전환된 열람**: 사진첩(앨범 목록·사진·라이트박스·개별/ZIP 다운로드),
  주보(최신·지난 주보), 내부 공지(목록·상세·첨부), 월례회 자료(목록·OPEN 자료
  열람 — 임원의 기간 외 열람 우회는 로그인 시에만), `/my` 홈(익명에게는 로그인

- **로그인·권한으로 남는 것**: 글 작성/수정/삭제·첨부 업로드(임원↑), 사진
  업로드/삭제·앨범 생성/삭제(임원↑), 주보 업로드/삭제(임원↑), 월례회
  업로드/기간관리/삭제/열람로그(임원↑), 회원 관리·역할 변경(전도사),
  사진 신고(회원), 내 정보(`/my/profile`, 본인)
- **⚠️ 폐기되는 기존 결정 2건** (PM이 충돌을 확인하고 명시적으로 선택):
  1. **8/24 초상권 결정 폐기** — "얼굴 식별 실인물 사진은 회원 전용"을
     "공개해도 되는 사진만 올린다"는 **운영 정책**으로 대체한다. 코드가 아니라
     사람이 지키는 규칙이 됐다 — 업로드하는 임원이 이 기준을 알아야 한다
  2. **월례회 열람 통제 완화** — 익명 열람이 허용되면서 "열람자 이름 워터마크"
     설계의 억제력이 축소된다 (익명 열람자는 이름이 없다). 열람기간(OPEN에만
     열람)은 유지된다
- **문서 게시판은 분류별로 갈린다 (PM 재확인 결과)**: **회의록은 공개,
  예산안은 임원 이상.** 헌금·지출 내역이 담기는 예산안만 남긴 것이다.
  화면에서는 권한이 없으면 예산안 탭 자체를 렌더하지 않고, 상세는 slug만으론
  분류를 알 수 없어 서버 판정에 맡긴다(권한 없으면 404로 존재를 숨김)
- **유지**: 가입·승인 흐름(/signup → 승인 대기 → 승인). 승인의 의미가
  "열람 자격"에서 **"권한 부여"**로 바뀐다. `/my`·`/admin` noindex와
  서비스워커의 비캐싱 정책은 일단 보수적으로 유지 (검색 노출은 별도 결정)
### 2차 인터뷰에서 확정한 8건 (2026-08-25)

| 항목 | 결정 |
|---|---|
| 문서 게시판 | **회의록 공개 · 예산안 임원 전용** |
| 월례회 워터마크(익명) | **익명용 대체 표기** — "익명 열람 · 열람시각 · 문서ID". 누가 유출했는지는 몰라도 언제 받은 사본인지는 남는다 |
| 사진 신고 | **익명도 신고 가능** — 사진첩이 공개되면서, 얼굴이 찍힌 비회원이 "내려달라"고 알릴 유일한 창구가 됐다. 스팸 신고는 임원이 거른다 |
| 검색엔진 노출 | **noindex 유지** — "로그인 없이 볼 수 있다"와 "구글 이미지 검색에 얼굴이 뜬다"는 다른 문제다 |
| 주소 구조 | **공개 주소로 이전** — `/my/{photos,bulletin,meetings,notices,documents}` → `/{...}`. 옛 주소는 영구 리다이렉트 |
| ZIP 대량 다운로드 | **기능 자체 제거** — 보는 것과 앨범을 통째로 받아가는 것은 다르다. 개별 다운로드는 유지. 백엔드는 `SPEC_API §6.8`을 구현할 필요가 없다 |
| 오프라인 캐싱 | **하지 않음(현행 유지)** — 공용 기기에 자료가 남는 문제는 공개 여부와 별개 |
| mock 자산 배포 | **현행 유지** — Vercel 데모를 띄우지 않으므로 `.vercelignore` 제외 그대로 |

### 작업하며 발견해 함께 고친 것

- ⚠️ **글쓰기 화면이 작성자에게 거짓 정보를 주고 있었다.** 공개 전환 후에도
  "공지(내부) — 회원만 볼 수 있습니다", "회의록 — 임원 이상만 볼 수 있습니다"로
  안내하고 있었다. 작성자가 "내부니까 괜찮겠지" 하고 민감한 내용을 쓸 수 있는
  자리라, 실제 공개되는 분류에는 "로그인 없이 누구나 볼 수 있습니다" 경고를
  띄우도록 고쳤다. **분류 이름(대상)과 접근 권한은 다른 것**임을 코드 주석에도 남겼다.
- 공개된 글에 붙어 있던 자물쇠(🔒)를 걷어냈다 — 잠기지 않은 글에 자물쇠를 달면
  반대 정보를 준다. 내부 공지는 "회원 대상" 뱃지로, 자물쇠는 예산안에만 남겼다.
- `/notices` 제목에서 "내부"를 뺐다 (누구나 보는 목록이므로).

- **미확정 사항**: 익명 월례회 열람 시 워터마크 문구의 최종 형태(백엔드와 협의) ·
  `/news`(공개 공지)와 `/notices`(공지 전체)가 둘 다 공개가 되어 역할이
  겹친다 — 합칠지 여부는 다음 결정 사항이다
- **구현**: `feat/fe-public-read-model` 브랜치. SPEC_FUNCTIONAL·SPEC_API의
  권한 표는 아직 이 결정을 반영하지 않았다 — 스펙 문서 갱신은 별도 작업

## 2026-08-25 — 월례회 업로드: 전송 구간만 진짜 진행률을 보여준다

  브라우저가 PDF를 보내고 → 서버가 변환을 다 끝내고 → 응답 하나가 온다.

  양쪽을 암시해서다 (`BACKEND_HANDOFF.md` 확정 요청 참고)

**사진·앨범 삭제**
- **배치**: 앨범 삭제는 목록 카드가 아니라 **앨범 상세 하단 위험 구역**, 사진

  - `next.config.ts`에 해당 경로 `X-Robots-Tag: noindex, nofollow` 추가
  - ⚠️ **둘 다 "검색에 안 뜨게" 하는 것일 뿐, URL을 아는 사람의 직접 접근은
    막지 못한다.** robots는 크롤러에게 부탁하는 규약이다
- **왜 지금 당장 위험하지는 않은가**: 아직 배포된 환경이 없고(M1 배포는 BE
