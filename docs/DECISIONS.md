# PM 결정 기록

PM(프론트엔드·인프라·기획 총괄)이 대화 중 구두로 전달한 스펙 결정·변경사항을
모아두는 로그다. **여기 있는 항목은 PM이 별도로 다시 요청하지 않아도, 결정이
나올 때마다 자동으로 추가된다** (`frontend/docs/HARNESS.md` §1 규칙).

목적: 백엔드 담당자를 포함해 이 대화에 없었던 사람도, 왜 화면/기능이 이렇게
바뀌었는지 나중에 추적할 수 있게 한다. `docs/SPEC_FUNCTIONAL.md`/
`docs/WIREFRAME.md`의 확정 스펙과는 별개로, **아직 그 문서에 반영되지 않은
최신 결정**을 여기서 먼저 확인할 수 있다.

형식: 최신 항목이 위에 온다.

## 2026-08-24 — 기능 완료된 `feat/fe-*` 브랜치는 머지 후 삭제한다

**결정**: `feat/fe-*` 작업 브랜치는 기능 작업이 끝나고 상위 브랜치
(`frontend_develop`)에 머지되면 **로컬과 GitHub 양쪽에서 삭제**한다.
브랜치 목록에 완료된 작업이 계속 쌓이면 지금 진행 중인 작업이 무엇인지
한눈에 안 보인다.

- **영역**: 협업·Git 운영 규칙 (프론트엔드 브랜치에 한정)
- **스펙 문서 반영 상태**: `docs/INTEGRATION.md` §6(브랜치 전략)에 삭제
  시점이 명시돼 있지 않다 — 이 항목이 그 공백을 메운다. `INTEGRATION.md`
  정식 반영은 아직 안 했다
- **삭제 전 확인 절차** (이번에 실제로 적용한 순서):
  1. 해당 브랜치가 상위 브랜치에 **완전히 병합됐는지** `git merge-base
     --is-ancestor`로 검증한다
  2. 로컬은 `git branch -d`(안전 삭제)를 쓴다 — 미병합이면 git이 거부하므로
     실수 방지가 된다. `-D`(강제)는 고유 커밋이 0개임을 따로 확인한
     경우에만 쓴다
  3. 원격은 `git push origin --delete`로 지운다
- **적용 범위 주의**: `feat/infra-*`는 서버·인프라 담당 영역이므로 FE가
  임의로 지우지 않는다. `main`·`develop`·`*_develop`은 영구 브랜치로 삭제
  대상이 아니다
- **연관 주의사항**: GitHub 저장소 설정 "Automatically delete head branches"는
  **계속 꺼둔다.** `frontend_develop` 같은 영구 브랜치가 PR head가 될 때
  자동 삭제되는 사고가 이전에 실제로 발생했다 (`docs/CICD.md` §4 관련)
- **미확정 사항**: 없음
- **구현**: 2026-08-24 M1·M2 완료 시점에 `feat/fe-*` 19개 삭제
  (`feat/fe-auth-core`, `feat/fe-signup-followup`, `feat/fe-password-reset`,
  `feat/fe-my-home`, `feat/fe-internal-notices`, `feat/fe-my-profile` +
  M1 시절 13개)

## 2026-08-21 — 디자인 톤: 베이지 + 그린 (로고가 나뭇잎이라서)

**결정**: 전체 디자인 톤을 베이지(배경) + 그린(강조색)으로 바꾼다. 기존
네이비+옐로우 팔레트를 대체한다. 근거: 로고가 나뭇잎 모양이라 그린이
브랜드와 더 맞는다.

- **영역**: 프론트엔드만 (디자인 토큰, `frontend/src/app/globals.css`)
- **스펙 문서 반영 상태**: `docs/WIREFRAME.md`/`docs/ARCHITECTURE.md`에 명시된
  색상표가 있다면 아직 갱신 전 — 실제 코드(토큰)가 최신 기준
- **미확정 사항**: 정확한 베이지/그린 색상값(hex)은 PM 확인 없이 임의로
  정함 — 브랜드 가이드가 따로 있으면 알려주면 교체
- **구현**: `frontend/src/app/globals.css` 색상 변수

## 2026-08-21 — 첫 화면 클릭 게이트: 신규/기존 방문자 분기

**결정**: `/`(루트)의 동작을 바꾼다. 기존에는 스플래시를 탭하면 사라지고
스크롤형 HOME(공지·우리는·모임안내 등, `WIREFRAME.md §1`)이 나타났다.
이제는 다음과 같이 분기한다:
- 스플래시에서 "처음 오시는 분" 영역을 클릭 → `/welcome` (안내 페이지)
- 그 외 아무 곳을 클릭 → `/login` (로그인 화면 — 이번엔 자리만 만들고,
  실제 로그인 기능은 이후 작업)

기존 스크롤형 HOME 콘텐츠는 삭제하지 않고 **`/home` 경로로 그대로 이동**한다
(PM 확인: "스크롤 콘텐츠는 그대로 두고 새 경로로 이동").

- **영역**: 프론트엔드만. 백엔드 영향 없음 (로그인 기능 자체는 아직 미구현)
- **스펙 문서 반영 상태**: `docs/WIREFRAME.md` §1(HOME)·이전 결정(아래 "홈 진입
  스플래시" 항목)을 대체한다. `SPEC_FUNCTIONAL.md` FR-PUB-01의 "상세" 란은
  이 변경을 아직 반영하지 않음 — 다음 스펙 정리 시 갱신 필요
- **미확정 사항**:
  - `/login`은 이번엔 자리만 만든 자리표시자(placeholder)다. 실제 인증
    로직·폼·API 연동은 M2에서 별도 진행 (`SPEC_FUNCTIONAL.md` FR-AUTH)
  - `/home`(구 스크롤 콘텐츠)에 재진입할 경로가 현재 UI 어디에도 없다 —
    당장은 직접 URL로만 접근 가능. 로그인 이후 흐름(`/my`)이나 헤더
    내비게이션에 다시 연결할지는 이후 결정 필요
- **구현**: `frontend/src/app/page.tsx`(게이트로 교체), `frontend/src/app/home/page.tsx`
  (기존 콘텐츠 이동), `frontend/src/app/login/page.tsx`(신규, placeholder)

## 2026-08-21 — 드림센터 실제 주소 확정

**결정**: 드림센터 주소는 **경남 김해시 분성로317번길 31**이다. 기존
코드의 "경남 김해시 가락로 117"은 확정 전 placeholder였다.

- **영역**: 프론트엔드만 (본당 주소는 여전히 미확정 — `WIREFRAME.md`의 ❓ 유지)
- **스펙 문서 반영 상태**: 코드(`/location`, `layout.tsx` JSON-LD)에는 반영함.
  `docs/WIREFRAME.md`/`docs/PLAN.md`에 있는 예시 주소는 아직 갱신 전
- **미확정 사항**:
  - 본당 주소(드림센터와 별개 건물)는 여전히 확인 필요
  - 지도 "이미지"는 만들지 못했다 — OpenStreetMap(Nominatim)이 이 도로명
    주소를 인식하지 못했고, 좌표를 지어내지 않았다. Kakao/Naver 지도
    JS SDK로 정확한 지도를 넣으려면 API 키 등록이 필요하다
    (`WIREFRAME.md §8`에서 이미 Phase 3로 미뤄둔 사항). 대신 카카오맵·
    네이버지도 "바로가기" 버튼은 실제 주소로 정확히 연결되도록 고쳤다
    (버튼을 누르면 그 서비스가 주소를 직접 해석하므로 좌표가 필요 없다)
  - 드림센터 외관·입구 사진은 인터넷에서 대신 채우지 않았다 — 특정 건물의
    실제 사진을 검증할 방법이 없어서, 틀린 사진을 실제 사진인 것처럼
    보여주는 것은 placeholder보다 더 나쁘다고 판단했다. 실제 사진은
    교회에서 촬영해 전달하는 것이 유일한 방법
- **구현**: `frontend/src/app/location/page.tsx`, `frontend/src/app/layout.tsx`
  (JSON-LD `address`)

## 2026-08-21 — 홈(`/`) 진입 시 단체사진 스플래시 화면 *(위 "클릭 게이트" 결정으로 대체됨)*

**결정**: 사이트 첫 진입(`/`) 시, 단체사진 위에 LIGHT 청년교회 로고와
텍스트가 겹쳐진 스플래시 화면을 먼저 보여준다. 한 번 탭하면 사라지고
메인 홈 화면(`WIREFRAME.md §1`)이 나타난다.

- **영역**: 프론트엔드만 (백엔드 API 영향 없음)
- **스펙 문서 반영 상태**: `docs/WIREFRAME.md §1 (HOME)`에는 아직 없음 —
  기존 HOME 와이어프레임보다 앞단에 추가되는 진입 레이어. 실제 HOME 구현
  시(WORKPLAN.md M1 "HOME" 태스크) `WIREFRAME.md`에도 정식으로 반영 필요
- **미확정 사항** (구현 시 임의로 정하지 않고 PM 확인 필요): *(위 새 결정으로
  해소됨 — 탭하면 사라지는 방식이 아니라 클릭 위치에 따라 분기하는 방식으로
  변경)*
  - 단체사진 실제 이미지 (현재 placeholder)
  - 방문마다 매번 보여줄지, 한 번 본 뒤에는 재방문 시 생략할지 (세션/영구
    저장 여부) — 이번 구현은 "매 방문 시 표시, 탭하면 그 방문에서만 해제"로
    가정하고 진행. 다르게 원하면 알려주면 수정
- **구현**: `frontend/src/app/page.tsx` + `frontend/src/components/`(스플래시
  컴포넌트) — 진행 상황은 관련 PR에서 추적
