# 개인정보 명단(CSV) 전달·보관 절차

관리자가 회원 명단(실명·생년월일·전화번호 등)을 CSV로 내려받아 저장소 밖
(관리자 PC, 이메일, 메신저 등)으로 전달할 때 지켜야 할 경로를 정의한다.
관련 결정: [`docs/records/DECISIONS.md` 2026-09-16](../records/DECISIONS.md),
Jira LIGHT-139/LIGHT-140.

## 1. 전달 방식: 임시 서명 링크

- 관리자가 명단 다운로드를 요청하면, 서버는 CSV 파일 자체가 아니라
  **짧은 시간(초안 10분) 내 만료되는 서명된 다운로드 URL**을 발급한다.
- 이메일·메신저 등으로 전달되는 것은 이 링크뿐이다. **CSV 파일을 직접
  첨부해서 보내지 않는다** — 첨부파일은 만료가 없고 전달 경로에 그대로
  남기 때문.
- 링크가 만료된 후에는 재요청해서 새 링크를 받아야 한다.

## 2. 데이터 흐름

```
관리자(회원 관리 화면) → 다운로드 요청
  → 서버가 CSV 생성 + 서명 URL 발급 (만료 시각 포함)
  → 관리자에게 서명 URL만 반환
  → 관리자가 URL을 열어 CSV 다운로드 (만료 전 1회 또는 제한 횟수)
  → 만료 후 해당 URL/파일은 서버에서 폐기
```

- 서명 URL 발급 방식(presigned URL vs 별도 토큰 서버), 정확한 만료 시간은
  아직 BE 설계 확정 전 — `DECISIONS.md`의 "미확정 사항" 참고.

## 3. 저장소 커밋 금지 원칙

- 실명·생년월일·전화번호가 담긴 CSV, 그리고 이를 생성/처리하는 과정에서
  나온 임시 파일은 **어떤 경우에도 git 저장소에 커밋하지 않는다.**
- 관련 로컬 스크립트·설정(`backend/application-local.yml`,
  `backend/run-local.ps1` 등)은 이미 `.gitignore` 처리되어 있다 — 새로
  추가하는 개인정보 관련 파일도 커밋 전 반드시 `.gitignore` 등록 여부를
  확인한다.
- 다운로드된 CSV를 로컬에 보관해야 하는 경우, 작업 종료 후 즉시 삭제한다.
