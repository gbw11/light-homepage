## 1. ⚠️ 구현하지 말 것 — ZIP 다운로드(`§6.8`)는 폐기됐다

```
GET /api/albums/{id}/download?ids=...     ← 만들지 않는다
```

사진첩이 공개되면서 **"앨범을 통째로 받아가는 경로"를 남기지 않기로** 했다.
보는 것과 대량으로 받아가는 것은 다른 문제라는 판단이다.

- **개별 다운로드(`§6.7`)는 그대로 유지된다.** 한 장씩은 익명도 받을 수 있다.
- FE에서는 관련 화면(선택 모드·하단 액션 바)과 API 호출을 전부 제거했다.
- 이미 작업했다면 되돌려도 되고, 그냥 두고 라우팅만 빼도 된다 — 어느 쪽이든
  FE는 호출하지 않는다.

## 2. 인가 매트릭스 — 익명 허용으로 바뀌는 열람 엔드포인트

기존 권한 `M`이던 아래가 **전부 익명 허용**이 된다.

| 엔드포인트 | 스펙 | 비고 |
|---|---|---|
| `GET /api/albums` | `§6.1` | 앨범 목록 |
| `GET /api/albums/{id}/photos` | `§6.4` | 사진 목록 (presigned URL 발급 포함) |
| `GET /api/photos/{id}/download` | `§6.7` | 개별 다운로드 302 |
| `GET /api/bulletins/latest` | `§5.1` | |
| `GET /api/bulletins` | `§5.2` | |
| `GET /api/bulletins/{id}` | `§5.3` | |
| `GET /api/posts` | `§3.1` | `NOTICE_MEMBER`·`MINUTES` 포함. **`BUDGET`만 예외 → §3** |
| `GET /api/posts/{idOrSlug}` | `§3.3` | 같음 |
| `GET /api/attachments/{id}/download` | `§4.2` | 글 권한 상속 → `BUDGET` 첨부만 `L` |

### ⚠️ `§7.2` 임원 우회는 세션이 있을 때만

`§7.1`의 "`L` 이상은 `status`와 무관하게 열람 가능"은 **로그인한 임원**에게만
적용한다. 익명 요청은 `status === "OPEN"`인 자료만 볼 수 있다.
(FE mock도 그렇게 구현했다 — 종료된 자료에 익명이 들어오면 "열람 기간이
종료되었습니다" 화면이 뜬다.)

### 권한이 그대로인 것 (변경 없음)

- **쓰기 전체**: 글 작성·수정·삭제·첨부 업로드(`L`↑), 사진 업로드·삭제·앨범
  생성·삭제(`L`↑), 주보 업로드·삭제(`L`↑), 월례회 업로드·기간수정·삭제·열람로그(`L`↑)
- **회원 관리**: 승인·거절·역할 변경(전도사), 새가족 명단(전도사), 저장공간 조회(`L`↑)
- `GET /api/auth/me` 등 auth 계열

## 3. 문서 분류별로 권한이 갈린다 + **403 대신 404**

`MINUTES`(회의록)과 `BUDGET`(예산안)이 이제 다르다.

| 분류 | 열람 권한 | 이유 |
|---|---|---|
| `NOTICE_PUBLIC` · `NOTICE_MEMBER` · `MINUTES` | **익명 허용** | |
| `BUDGET` | **`L` 이상 유지** | 헌금·지출 내역이 담긴다 |

### ⚠️ 권한 없는 예산안 요청에는 `404`를 준다

```
GET /api/posts/budget-2026-h2   (익명 또는 일반 회원)
→ 403 FORBIDDEN   ❌
→ 404 NOT_FOUND   ✅
```

`403`은 **"그 문서가 존재한다"는 사실을 알려주는 셈**이다. 예산안은 존재 자체를
숨긴다. `SPEC_API §3.3`이 원래 그렇게 규정하고 있고, FE mock도 404로 구현했다.

- 목록(`§3.1`)에서 `category=BUDGET`을 권한 없이 요청하면 `403`이 맞다
  (분류의 존재는 이미 공개된 정보이므로). FE는 애초에 그 요청을 보내지 않는다 —
  권한이 없으면 예산안 탭 자체를 렌더하지 않는다.

## 4. 월례회 워터마크 — 익명 열람자에게 무엇을 박는가 (`§7.3`)

기존 설계는 `이름 + 연락처 뒷4자리 + 열람시각`을 픽셀에 합성하는 것이었다.
**익명 열람자는 박을 이름이 없다.**

PM이 정한 것 (`DECISIONS.md` 2026-08-25):

| 열람자 | 워터마크 |
|---|---|
| 로그인 사용자 | `{이름} {연락처 뒷4자리}` + 열람시각 **(기존과 동일)** |
| 익명 | `익명 열람` + **열람시각 + 문서ID** |

- 누가 유출했는지는 특정할 수 없지만 **언제 받은 사본인지는 남는다** — 유출
  시점이 드러나는 것만으로 억제력이 있다는 판단이다.
- 서버는 **세션 유무로 두 갈래**만 만들면 된다.
- FE는 뷰어 하단 안내 문구를 로그인 상태에 따라 이미 갈라 놓았다. 익명에게는
  "열람 시각과 문서 번호가 함께 인쇄되어 있습니다 / 로그인해서 열람하면 이름과
  연락처 뒷자리도 함께 인쇄됩니다"로 나온다. **문구와 실제가 어긋나면 안 되니
  구현이 이 표와 다르면 알려달라.**
- 열람 로그(`§7.7`)에 익명 열람을 어떻게 남길지는 BE 판단에 맡긴다
  (남기지 않아도 FE 화면은 문제없다).

## 5. 사진 신고(`§6.10`)는 익명도 허용한다

요청 스키마는 그대로 (`{ "reason": "..." }`).

**왜 익명을 허용하는가**: 사진첩이 공개되면서, **사진에 얼굴이 찍힌 비회원이
"내려달라"고 알릴 유일한 창구**가 이 엔드포인트가 됐다. 로그인을 요구하면 정작
요청해야 할 당사자가 요청할 수 없다.

- 스팸·장난 신고가 들어올 수 있다는 점은 PM도 알고 있고, **임원이 거르는 것**으로
  정리됐다.
- 서버 쪽 rate limit이 필요하다고 판단되면 넣어도 된다 — FE는 실패 응답을
  그대로 화면에 보여준다. 필요하면 에러 코드만 알려달라.

## 6. 🙏 신규 요청 — 전도사용 **계정 생성** API (결정 1건 필요)

**배경**: 회원가입 진입점을 화면에서 숨겼다. 공개 열람 전환으로 **일반 회원
계정이 비회원보다 할 수 있는 일이 없어져서**, "가입하면 뭔가 열린다"는 기대를
만들지 않기로 한 것이다. 계정이 실제로 필요한 사람은 **임원·전도사뿐**이고,
그 계정은 전도사가 만들어 준다.

- **지금 상태**: `/signup` 라우트와 폼은 살아 있어서 **주소를 직접 알려주면**
  가입할 수 있다. 급한 대로 이렇게 운영 가능하므로 **이 항목은 급하지 않다.**
- **제안**: `POST /api/admin/members` — 권한 **전도사(`P`)**

```json
// 요청
{ "name": "박OO", "email": "...", "phone": "010-...", "village": "1", "role": "LEADER" }

// 응답 (방식 A — 임시 비밀번호)
{ "id": "12", "tempPassword": "..." }

// 응답 (방식 B — 초대 링크)
{ "id": "12", "inviteUrl": "https://.../signup/invite?token=..." }
```

### ⚠️ 정해야 할 것 — A와 B 중 어느 쪽인가

| 방식 | 장점 | 필요한 것 |
|---|---|---|
| **A. 임시 비밀번호** | 이메일 인프라 불필요 | 첫 로그인 시 비밀번호 변경 강제 |
| **B. 초대 링크** | 비밀번호를 사람 손으로 전달하지 않음 | 만료 토큰 + **이메일 발송 인프라** |

**이메일 발송이 아직 없다면 A가 현실적이다.** 어느 쪽으로 갈지 알려주면 FE가
관리 화면에 폼을 붙인다. 인가 매트릭스(`ARCHITECTURE §5.3`)에도 이 행을 추가해야 한다.

## 7. 배경 — 이 전환으로 폐기된 기존 결정 2건

PM이 충돌을 확인하고 명시적으로 선택한 것이다. BE가 이전 결정을 근거로 작업하고
있었다면 기준이 달라졌으니 확인이 필요하다.

1. **8/24 초상권 결정 폐기** — "얼굴이 식별되는 실인물 사진은 회원 전용"이
   **"공개해도 되는 사진만 올린다"는 운영 정책**으로 대체됐다. 코드가 아니라
   사람이 지키는 규칙이 됐다.
2. **월례회 열람 통제 완화** — 익명 열람이 허용되면서 워터마크의 억제력이
   축소된다. 열람 기간(`OPEN`에만 열람) 자체는 유지된다.

**noindex는 유지된다** — "로그인 없이 볼 수 있다"와 "구글 이미지 검색에 얼굴
사진이 뜬다"는 다른 문제라, 자료 경로는 계속 검색엔진 색인을 막는다.

## 9. FE가 이미 끝낸 것 (참고)

- 라우트 이전: `/my/{photos,bulletin,meetings,documents}` → `/{...}`,
  `/notices` → `/news` (모두 308 영구 리다이렉트). **API 경로는 변동 없다.**

- 전반적인 GET 재요청 감소 — react-query `staleTime` 60초 적용으로 창 포커스
  복귀 시의 중복 조회가 사라졌다.
