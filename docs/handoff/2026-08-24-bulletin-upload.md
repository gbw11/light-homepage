## 0. 한 줄 요약

FE는 업로드·교체·삭제 화면을 다 만들었다. **착수 전에 결정할 것이 1건**(§1 교체
방식), **확인할 것이 1건**(§2 multipart 파트 이름)이다.

`POST /api/bulletins` 하나만 계약대로 받아 주면 화면은 그대로 붙는다.

---

## 1. ⚠️ 교체를 한 요청으로 처리할 수 있게 해 주세요

`§5.4`는 같은 날짜가 있으면 `DUPLICATE`를 주고 **"교체 여부를 FE가 확인 후 재요청"**
이라고만 정했다. 그런데 **교체용 엔드포인트가 없다.** 그래서 FE는 이렇게 구현했다.

```
POST /bulletins                    → 409 DUPLICATE
  → 사용자에게 "기존 주보를 지우고 새로 올릴까요?" 확인
  → GET  /bulletins                → 날짜로 기존 id를 찾는다
                                     (DUPLICATE 응답에 id가 없다)
  → DELETE /bulletins/{id}         → ⚠️ R2 객체까지 지운다. 되돌릴 수 없다
  → POST /bulletins                → 재시도
```

**문제**: `DELETE`가 성공하고 마지막 `POST`가 실패하면 **기존 주보가 사라진 상태로
남는다.** 사용자가 할 수 있는 일이 없다. 화면은 이 경우 "기존 주보를 지웠지만 새로
올리지 못했습니다"라고 정직하게 말하지만, 그게 위로가 되지는 않는다.

### 요청 (택 1)

| 안 | 내용 | FE 영향 |
|---|---|---|
| **A (권장)** | `POST /api/bulletins`에 `replace=true`를 두거나 `PUT /api/bulletins?serviceDate=...`를 추가해 **한 트랜잭션에서 기존 것을 지우고 새로 저장**한다. 실패하면 아무것도 바뀌지 않는다 | 확인 → 호출 1회로 단순해진다 (**지금 코드에서 20줄이 빠진다**) |
| B | `DUPLICATE` 응답 본문에 **기존 `id`를 담아 준다** | 목록 조회 1회가 줄지만, 중간 실패 문제는 그대로 남는다 |

**A를 권한다.** 주보는 매주 갱신되는 자료라 교체가 예외가 아니라 일상이다.

## 2. multipart 파트 이름 — 확인 필요

`§5.4` 표에는 `pages[]`로 적혀 있다. FE는 **`pages`** 라는 이름으로 파일 파트를
N개 append한다 (Spring의 `List<MultipartFile> pages`가 받는 형태).

```
Content-Type: multipart/form-data; boundary=...

serviceDate: "2026-08-24"
pages: <file>   ← page-1.webp
pages: <file>   ← page-2.webp
```

- 파트 이름이 **대괄호를 포함한 `pages[]`** 여야 하면 알려줄 것. `real.ts` 한 줄이다
- ⚠️ **append 순서가 곧 페이지 번호다.** FE는 화면에서 사용자가 정한 순서 그대로
  보낸다. 서버가 **파일명이나 업로드 시각으로 다시 정렬하면 순서가 깨진다** —
  앞/뒷면이 바뀌면 주보를 읽을 수 없고, 이게 `FR-BUL-05`의 핵심 요구사항이다
- 파일명은 `page-1.webp`, `page-2.webp` … 로 붙지만 **의미를 두지 말 것.**
  순서의 근거는 파트 순서다

---

## 3. FE가 보내는 이미지

| 항목 | 값 |
|---|---|
| 포맷 | **WebP** (`ARCHITECTURE §4.2`) |
| 크기 | **장변 2048px**. 확대하지 않는다 — 원본이 더 작으면 그 크기 그대로 |
| EXIF 회전 | **FE가 이미 적용**했다. 서버가 다시 적용하면 두 번 돌아간다 |
| 썸네일 | **서버가 만들어야 한다.** `§5.2`의 `thumbUrl`은 FE가 보내지 않는다 |

주보는 사진첩과 달리 **썸네일을 열람에 쓰지 않는다** — 글자가 작아서 `§5.1`의
`pages[].url`(2048px)을 바로 로드한다 (`FR-BUL-03`). `thumbUrl`은 지난 주보 목록의
작은 표지에만 쓰인다.

| c | `DELETE` 후 `GET /bulletins/latest`가 즉시 그 다음 주보를 주는가 | 삭제 성공 후 `["bulletins"]` 쿼리를 전부 무효화해 다시 읽는다 |

## 5. 인가

`POST /api/bulletins` · `DELETE /api/bulletins/{id}` **둘 다 `L`(임원)**.

FE는 임원 미만에게 업로드 화면과 삭제 버튼을 감추지만 **그건 UI 편의일 뿐이다**
(`WORKPLAN §5.1`). 일반 회원이 `/admin/bulletin/upload`를 직접 입력해도 서버가
막아야 한다.

## 6. BE 작업 체크리스트

- [ ] **§1 결정** — 교체를 한 요청으로 할지 (A/B)
- [ ] **§2 확인** — multipart 파트 이름 (`pages` vs `pages[]`) · **순서 보존**
- [ ] `POST /api/bulletins` — 페이지 순서대로 `pageNo` 부여 + R2 저장 + **썸네일 생성**
- [ ] `DELETE /api/bulletins/{id}` — R2 객체까지 삭제
- [ ] 용량 집계 반영 (`STORAGE_LIMIT` 검사 대상에 주보 포함)

**통합 검증 (FE와 함께)**: 2장짜리 주보를 **일부러 뒤집힌 순서로 골라 ↑↓로
바로잡은 뒤** 올려서, 뷰어에 1→2 순서대로 나오는지 확인한다. 순서가 이 기능의
전부다.
