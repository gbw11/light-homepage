   **이게 안 맞으면 2번은 볼 필요도 없다**

### 1.2 🔴 사진이 든 옛 배포 삭제 — 새 Production 배포가 생긴 뒤에만 가능

Vercel은 배포마다 고유 URL을 **영구 보존**한다. 1.1이 통과해도 **어제 오전
`6e47df3` 배포는 자기 URL에서 계속 실인물 사진을 서빙한다.**
Deployments에서 **`d0f8a0f`(사진 제거) 이전 배포를 전부 삭제**한다
(`infra/vercel/README.md §2.5`).

⚠️ **이걸 빼먹고 나중에 SSO 보호를 풀면 사진 제거가 무의미해진다** — 보호 해제
체크리스트(§3)에도 넣어놨지만, 지금 지우는 것이 안전하다.

### 1.3 Ignored Build Step — **1.1이 통과한 뒤에만** 설정

BE 커밋의 Vercel 오탐(§3.3)을 막는 설정인데, **일부러 미뤘다.** 이 설정의
오작동 증상이 "프론트 변경이 배포되지 않음"이고, 오늘까지가 정확히 그
상태였다 — 정상 배포가 실측으로 확인돼야 오작동과 구별할 수 있다.
절차·함정(**종료 코드 0 = 건너뜀, 직관과 반대**)은 `infra/vercel/README.md §5.5`.

## 3. ⚠️ 오늘 드러난 것

### 3.1 🔴 프로덕션이 13커밋 동안 동결돼 있었다 — Production Branch가 `main`이었다

어제 "PR #95 머지로 배포 사이트가 실제로 고쳐졌다"고 적었는데, 오늘 브라우저
실측에서 `/photos/retreat-2026/thumb/p001.webp`가 **여전히 200**이었다.
아이콘도 200이었으므로 유효한 양성이다.

원인: **Vercel Production Branch가 `main`.** `main`은 develop보다 283커밋
뒤처진 문서 전용 브랜치다. Vercel은 프로젝트 연결 시 **첫 배포를 브랜치와
무관하게 Production으로 표시**하므로 `6e47df3`이 Production이 됐고, 이후
develop 머지는 전부 Preview가 되어 별칭이 **어제 오전 상태로 영구 동결**됐다.
반영 안 된 13커밋에 **#94(사진 제거)·#92(빌드 수정)**가 포함돼 있었다.

**앞의 두 사례(.vercelignore·Jenkins)와 성질이 다르다** — 그때는 "장치가
무효"였고, 이번엔 **"장치가 켜져 있다고 믿었다."** 문서(§1①)에 `develop`이
적혀 있었을 뿐, **문서의 값과 실제 설정을 대조한 적이 없었다.**

- 노출은 없었다 — Deployment Protection(Standard)이 전 기간 유일한 방어였다
- 조치: 설정 변경(PM) · `§2⓪ 서빙 커밋 대조` 절차 신설 · `§2.5`(Redeploy/
  Promote 금지 이유 · 옛 배포 삭제) · README에 "main은 뒤처진 것이 정상,
  배포 설정이 main을 가리키면 안 된다" (#97)
- ⚠️ 파생 교훈: `§5`의 "빌드 실패는 서비스 중단이 아니다"는 안전 장치가 아니라
  **침묵 장치**다 — 고친 것이 반영되지 않아도 사이트는 멀쩡해 보인다

### 3.2 로컬에서 백엔드 테스트가 전멸했는데 코드 문제가 아니었다 — 2건

머지된 develop에서 `./gradlew test`가 46개 클래스 전부 `ClassNotFoundException`
으로 죽었다. 코드 결함으로 보였지만:

1. **저장소 경로의 한글(`light홈페이지`)이 Gradle 테스트 워커를 죽인다** —
   같은 코드·같은 DB를 ASCII 경로에 복사하면 통과한다(대조 실측). 해법은
   `GRADLE_OPTS`로 인코딩을 시스템 코드페이지(**MS949**)에 맞추는 것.
   ⚠️ **UTF-8로 올리면 반대로 더 깨진다** — 실측으로 확인했다
2. **로컬 테스트 DB 부재** — 기존 `light-db` 컨테이너(user `light`)에
   `light_test`를 만들어 해결

두 우회 적용 후 **192개 테스트 전부 통과** — develop의 백엔드는 건강하다.
절차는 `docs/ops/TOOLCHAIN.md §4.5`(#101). **로컬 판단이 어려우면 CI를
믿는다** — CI는 이 두 문제가 구조적으로 없다.

### 3.3 BE 커밋의 Vercel 오탐이 예고대로 발생했다

#100(backend_develop → develop)에서 Vercel 체크가 `Deployment was blocked`로
