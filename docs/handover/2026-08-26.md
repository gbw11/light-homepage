## 5. 오늘 한 것

### 5.0 ⚠️ 가장 큰 것 — 인가 매트릭스 2개가 전환 전 값이었다
`SPEC_API §10`과 `BACKEND_TASKS §6`은 각각 **"마지막 방어선"·"BE의 최우선
산출물"** 이라고 문서 스스로 밝히는 표인데, **8/25 권한 전환이 반영되지 않은
채 열람 대부분이 `401`로 남아 있었다.**

BE가 이 표대로 테스트를 작성했다면 **공개돼야 할 열람이 전부 잠긴 채로
"인가 테스트 통과"가 떴을 것이다.** 잠긴 것은 테스트가 잡아주지 않는다 —
막는 방향의 실수는 통과처럼 보인다.

두 표를 새 기준으로 다시 만들고, **틀리기 쉬운 4가지**를 표 아래에 붙였다.
그중 하나는 표를 고치다 발견한 것이다:

> **`PENDING`이 `GUEST`보다 권한이 낮으면 안 된다.** 전환 전 표는 `PENDING`을
> 열람 전부 `403`으로 두고 있었다. 그대로 두면 **가입한 사람이 가입 안 한
> 사람보다 못 보게 된다.** 전환 논의에서 아무도 짚지 않았던 구멍이다.

### 5.1 `SPEC_API.md` — 권한 모델 전환 반영 (v1.0 → v1.1)
8/25 전환이 `SPEC_FUNCTIONAL`·`WIREFRAME`에만 반영돼 있었고, **BE가 실제로
읽는 계약서인 `SPEC_API`는 옛 권한 표 그대로였다.**

- 문서 머리에 전환 안내 블록 (요약 3줄 + 근거 문서 링크)
- **개별 `권한` 줄 12개를 `M` → `G`로** (`§3.2` `§3.3` `§4.2` `§5.1~5.3` `§6.1`
  `§6.4` `§6.7` `§6.10` `§7.1~7.3`)
- `§1.5` — 열람에는 `M`이 거의 남지 않는다는 설명. 남은 3곳(`§2.11~2.13`)은
  **본인 계정 관련**이라 맞다
- `§3.1` 분류 표 — `NOTICE_MEMBER`·`MINUTES` 열람을 "누구나"로. **`BUDGET`만 `L`**
  + 권한 없으면 **404**(403은 "그 문서가 존재한다"를 알려주는 셈)
- `§4.2` — "로그아웃 상태 접근은 `UNAUTHORIZED`"가 전환과 **정면으로 모순**이었다.
  첨부는 원글 분류를 다시 확인하고 예산안 첨부만 `L`(없으면 404)로 정정
- `§6.8` ZIP — **취소선 + "구현하지 마세요"** 로 명시
- `§7.3` 워터마크 — **세션 유무 두 갈래 표** 추가 (익명은 `익명 열람` + 열람시각 + 문서ID)
- `§7.1`·`§7.3` — 임원의 기간 무관 열람이 **로그인 세션이 있을 때만**임을 명시
- **`§9.2 GET /api/sermons` 신설** — PR #70의 `[CONTRACT]`가 `BACKEND_HANDOFF`에만
  있고 스펙에는 없었다. 해당 인계 문서가 "`SPEC_API §10` 표에 추가돼야 한다"고
  직접 요청하고 있었다. BE가 정해야 할 3가지(캐시 기간·채널 vs 재생목록·실패 응답)도 함께
