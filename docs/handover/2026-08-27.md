## 3. ⚠️ 오늘 드러난 것 — "믿고 있던 방어가 없었다" 세 건

오늘의 핵심이다. 셋 다 **증상이 없어서** 따로따로 발견됐다.

### 3.1 `.vercelignore`가 실인물 사진을 막지 못했다

8/25부터 "배포에서 제외됐다"고 믿고 있었다. Vercel 첫 배포에서 실측한 결과
`/photos/retreat-2026/thumb/p001.webp`가 **200으로 서빙됐다.** Git 연동 배포에서는
그 파일이 효과가 없다.

⚠️ **판정 방법도 틀렸었다.** 처음엔 자산 경로가 404인 걸 보고 "제외됐다"고
판단할 뻔했는데, **사이트 전체가 404였기 때문**이었다. "있어야 하는 자산(아이콘)도
함께 확인"으로 바꾸자 실제 상태가 드러났다. **음성 결과 하나로 판정하면 안 된다.**

→ 1안(자산을 `public/` 밖 + route handler)으로 전환. 그 기간의 유일한 방어는
"배포가 없었다는 사실"과 배포 후의 **SSO 보호**였다.

### 3.2 Jenkins가 하루 종일 돌지 않아 시크릿 스캔이 비어 있었다

커밋 상태를 조회해보니 `5b263ca` 이후 오늘 커밋 **전부에 Jenkins 상태가 없다.**
Jenkins는 PM 로컬 PC에 있어 PC가 꺼지면 멈춘다.

→ Secret Scan을 GitHub Actions로 이관(PR #90). **사람의 PC 상태에 달린 방어는
방어가 아니다** — 배포 트리거를 옮긴 8/26 결정과 같은 논리다.

### 3.3 커넥션 풀이 Neon을 상시 가동시키고 있었다

어제 핑 경로를 고쳐 "이제 Neon이 정지된다"고 기록했는데, **HikariCP 6.3.3의
`keepaliveTime` 기본값이 0이 아니라 2분**이었다(바이트코드로 확인). 유휴 커넥션에
2분마다 쿼리가 나가 자동 정지가 걸리지 않았다.

→ `keepalive-time: 0` · `minimum-idle: 0` · `idle-timeout: 4분`.
`DataSourcePoolConfigTest`가 회귀를 막는다.

### 4.3 과금 방지 설계 — 1차 방어 완성

**한도를 지키는 방식에서 과금 경로를 없애는 방식으로 전환했다.**

- ✅ **GitHub·Render·Neon·Vercel 네 곳 모두 결제 수단 미등록** (PM 확인)
- 초과해도 **과금이 아니라 서비스 정지**로 나타난다
- 누수 3경로 차단(§3.3) · Render Auto-Deploy `Off` · Health Check Path 교체
- 핑 스케줄을 24시간이 아니라 06:00~24:00으로 (744h → 558h) — **"상시"를 노린
  설정이 월말에 서버를 멈추게 하는** 산수를 피했다

### 4.4 서버 최적화

콜드스타트(`-Xms128m`) · 재배포 요청 유실(`graceful` + 20s) · 메모리(스레드 200→20) ·
GC 고정(`UseSerialGC`). ⚠️ **효과 수치는 실측하지 못했다** — Docker 데몬이 꺼져
있었다. `application.yml` 8줄이 BE 소유라 승인 대상이다.

⚠️ **응답 압축은 효과가 확인되지 않았다** — `Content-Encoding: gzip`은 붙지만
content-type으로 갈리는 패턴이라 **Render 앞단 Cloudflare 소행으로 보인다.**
설정은 no-op일 수 있다.
